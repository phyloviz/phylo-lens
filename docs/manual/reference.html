API reference

The browser library and HTTP service have separate APIs. Use the browser library to embed a viewer. Use the HTTP API to build your own frontend or process trees from a script.

Choose an API#

Reference What you will find
Browser API Create a view, load a tree, handle selection, change appearance, search, expand branches and export PNGs.
Browser types Options, sample information, identifiers and the complete custom-adapter request and result types.
HTTP API Every endpoint, request fields, real response examples and error handling.
HTTP field reference All nested request and response fields, allowed values and limits.

These references are part of this manual. You can also download the OpenAPI schema for tooling or client generation.

Implementation notes#

The repository contains the detailed design notes. Read these when you need to understand how the service or renderer works:

  • Architecture and runtime flow.
  • Data model and sample observations.
  • Preparation pipeline and levels of detail.
  • Tree indexing, expansion and folding, and rendering.

Algorithms and references#

PhyloLens uses PhyloLib for typing-data inference and Graphviz for the initial global layout. The algorithm references list the published methods and explain which parts are specific to PhyloLens.

A technical root sets a starting point for navigation; it does not establish ancestry. Original isolates, shared typing profiles and visual groups also have different meanings. Keep those distinctions in mind when reading counts.
