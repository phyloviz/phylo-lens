HTTP API

Use the HTTP service from your own frontend, script or notebook. Requests and responses use JSON. Graph routes are under /api/graph; service information is at /health.

This page describes API contract 1. Each endpoint links to its full request and response fields. You can also download the OpenAPI schema. A running service exposes its current schema at /openapi.json and interactive documentation at /docs.

Prepare, then read#

  1. Check GET /health.
  2. Submit POST /api/graph/prepare.
  3. Poll GET /api/graph/prepare/{job_id} until ready or failed.
  4. Keep the returned dataset_id and layout_version for later reads.

Preparation is asynchronous; viewport, search and revision calls return their result directly. Repeated identical preparation can reuse a job or layout. A metadata or root revision returns a new version; use that version for subsequent reads.

Set Content-Type: application/json on requests with a body. Authentication is not implemented by the service; configure it at your deployment boundary if needed. Browser access must satisfy your service’s CORS policy.

The examples below were captured from the service using (A:1,B:2)Root;. Replace the example job and layout identifiers with the values returned by your own requests.

Method Path Success
GET /health 200
POST /api/graph/prepare 202
GET /api/graph/prepare/{job_id} 200
POST /api/graph/viewport 200
POST /api/graph/region 200
POST /api/graph/search 200
POST /api/graph/components 200
PUT /api/graph/ancillary 200
POST /api/graph/connections 200

GET /health#

Read service information before connecting. API contract version 1 is supported. The service_version value identifies the implementation release.

No request body.

Example request

curl http://localhost:8000/health

Response · 200

Fields: record of string.

{
  "status": "ok",
  "service_version": "0.4.0",
  "api_version": "1"
}

POST /api/graph/prepare#

Submit Newick or typing data. Validation and normalization run before the request is accepted. Preparation then runs as a background job.

Request

Field Type Required Description
format SourceFormat yes Input format.
dataset_name string no Name used to identify the dataset.
minimum length 1; default "dataset"
content string yes Raw Newick, typing-table or ancillary-table content, according to the operation.
minimum length 1
options NormalizeOptions no
metadata_schema array of AncillaryField no Alias for ancillary_schema. Do not send both names.
metadata_by_node_id record of record of string | number | boolean | null no Alias for ancillary_by_node_id. Do not send both names.
ancillary_data AncillaryDataRequest | null no Table of observations joined through its identifier column.
sfdp_options SfdpOptions no Global Graphviz layout settings.
lod_options LodOptions no Preparation policy for protecting small components.
distance_cutoff number | null no Keep tree edges at or below this distance before preparation. Zero is valid. All distances must be known.
typing_options FullMstOptions | GoeBurstOptions | null no Typing inference method and optional maximum nLV. Only valid for typing_data.

Example request

curl -X POST http://localhost:8000/api/graph/prepare \
  -H 'Content-Type: application/json' \
  -d '{"format":"newick","dataset_name":"example-tree","content":"(A:1,B:2)Root;"}'

Response · 202

Fields: GraphPrepareJob. 

{
  "job_id": "db7d01e3dd6044c3939818ba9c240256",
  "status": "pending",
  "dataset_id": "example-tree"
}

For typing data, use format: "typing_data" with typing_options: { "algorithm": "goeburst", "nlv": 3 }, or { "algorithm": "goeburstfullmst" } for all levels. Standard goeBURST defaults to nLV 3; Full MST does not accept nlv. The result confirms the applied typing options and cutoff. Verify those confirmations before describing the result as filtered.

Current input names are ancillary_schema and ancillary_by_node_id. API v1 also accepts the aliases metadata_schema and metadata_by_node_id, which appear in OpenAPI. Do not send both names for one field. Responses retain v1 names such as metadata and metadata_schema.

Missing typing loci use the shared complete-locus policy described in Input formats. Graphviz settings are in sfdp_options; small-component protection is in lod_options.

GET /api/graph/prepare/{job_id}#

Poll using the job_id from the accepted request. Pending jobs have no result. Ready jobs include result; failed jobs include error and optional error_details. A failed job still returns HTTP 200.

job_id is a required path parameter.

Example request

curl http://localhost:8000/api/graph/prepare/db7d01e3dd6044c3939818ba9c240256

Response · 200

Fields: GraphPrepareStatus. 

{
  "job_id": "db7d01e3dd6044c3939818ba9c240256",
  "status": "ready",
  "result": {
    "dataset_id": "example-tree",
    "layout_version": "80a675d88f05e453",
    "node_count": 3,
    "edge_count": 2,
    "cluster_count": 3,
    "lod_tier_count": 1,
    "technical_roots": [
      "root"
    ],
    "layout_status": "ready",
    "warnings": []
  }
}

Current preparation publishes ready layouts. Previously stored degraded layouts remain readable. The default browser adapter polls every 1,000 ms with no overall wait timeout. Those are client defaults, not server request fields.

Supply all four spatial bounds together, with each maximum at least its minimum. Bounds are ignored when expanding an explicit cluster. A node budget limits primary retrieval; attachment neighbours can make the final response larger.

Optional null fields are omitted. For example, a root’s tree_index.parent_id can be absent. Do not assume an omitted branch distance is zero.

Annotation reuse is optional. Omit both reuse fields for complete node observations in every response.

POST /api/graph/search#

Search identifiers and sample values across the prepared dataset or selected component. Matching original isolates identify their profile node. total_count counts matching profiles before the limit.

Request

Field Type Required Description
component_id string | null no Restrict a read to this prepared component; omit for the overview.
dataset_id string yes ID returned by preparation.
minimum length 1
layout_version string | null no Pin the published version you want to read. When optional and omitted, the service selects the latest published version.
query string yes Non-empty identifier or sample-value text.
minimum length 1
limit integer no Maximum results on this page.
minimum 1.0; maximum 500.0; default 25

Example body

{
  "dataset_id": "example-tree",
  "layout_version": "80a675d88f05e453",
  "query": "A",
  "limit": 25
}

Response · 200

Fields: GraphSearchResponse. 

{
  "dataset_id": "example-tree",
  "layout_version": "80a675d88f05e453",
  "query": "A",
  "matches": [
    {
      "node_id": "a",
      "score": 100,
      "matched_text": "a",
      "cluster_id": "lod_0_a",
      "x": 0.02,
      "y": 0.02
    }
  ],
  "total_count": 1
}

Search trims the ends of the query and compares identifiers without case sensitivity. Original isolate punctuation, internal whitespace and leading zeros remain meaningful. Ranking is exact ID (100), prefix (60), substring (40), then ancillary-value match (20). Ties use the profile ID.

PUT /api/graph/ancillary#

Apply a new table to an explicit published version. This replaces sample values and their schema, including directly supplied fields. Omitted fields and unmatched records do not keep old values. A successful update publishes a new version while preserving the original.

Request

Field Type Required Description
dataset_id string yes ID returned by preparation.
minimum length 1
layout_version string yes Pin the published version you want to read. When optional and omitted, the service selects the latest published version.
minimum length 1
ancillary_data AncillaryDataRequest yes Table of observations joined through its identifier column.

Example body

{
  "dataset_id": "example-tree",
  "layout_version": "80a675d88f05e453",
  "ancillary_data": {
    "format": "csv",
    "join_column": "ID",
    "content": "ID,country\nA,Portugal\nB,Spain\n"
  }
}

Response · 200

Fields: GraphAncillaryResponse. 

{
  "dataset_id": "example-tree",
  "layout_version": "ec60da2f96a7d738b2b321331942d5e559e1c4d4c9d1a7a3fe8875cf1bcfd066",
  "matched_node_count": 2,
  "warnings": [
    "Ancillary data did not include rows for 1 joinable nodes."
  ]
}

The source must be ready or degraded. Typing tables join original isolate identifiers and accept at most one row per isolate. Newick tables join labelled node IDs with slug fallback and can contain several rows per node. Unmatched rows are warnings; a table matching no nodes fails.

The operation reuses geometry and cluster memberships. It does not repeat PhyloLib inference, Graphviz layout or LoD construction. Publication is transactional; the original version remains readable.

POST /api/graph/connections#

Calculate an overlay within the prepared components. For typing, supply the same profile input used for preparation. For Newick, the service uses stored tree-path lengths. No tree edge or coordinate is changed.

Request

Field Type Required Description
dataset_id string yes ID returned by preparation.
minimum length 1
layout_version string yes Pin the published version you want to read. When optional and omitted, the service selects the latest published version.
minimum length 1
format SourceFormat yes Input format.
content string yes Raw Newick, typing-table or ancillary-table content, according to the operation.
minimum length 1
threshold number yes Inclusive nonnegative distance limit. Typing thresholds must be whole numbers.
minimum 0.0
max_connections integer no Reject the whole overlay if this output limit would be exceeded.
minimum 1.0; default 50000

Example body

{
  "dataset_id": "example-tree",
  "layout_version": "80a675d88f05e453",
  "format": "newick",
  "content": "(A:1,B:2)Root;",
  "threshold": 3
}

Response · 200

Fields: GraphConnectionsResponse. 

{
  "dataset_id": "example-tree",
  "layout_version": "80a675d88f05e453",
  "metric": "patristic",
  "threshold": 3.0,
  "edges": [
    {
      "id": "distance:a:b",
      "source": "a",
      "target": "b",
      "distance": 3.0
    }
  ]
}

Thresholds are inclusive. Distinct zero-distance pairs are included; tree edges, self-links and unnamed junctions are excluded. The original typing input must match preparation. Matching node IDs alone does not authenticate its allele values.

Fractional typing thresholds, unknown branch distances and exceeded connection limits return 422. Exceeding the limit returns no partial edge list.

POST /api/graph/root#

Set node_id to a canonical node ID to reorient its component, or explicitly send null to restore all preparation roots. Nodes, tree edges, distances, observations and coordinates are preserved. Rooted indexes and detail groups are rebuilt in one transaction.

Request

Field Type Required Description
dataset_id string yes ID returned by preparation.
minimum length 1
layout_version string yes Pin the published version you want to read. When optional and omitted, the service selects the latest published version.
minimum length 1
node_id string | null yes Canonical node identifier. For rooting, explicitly send null to restore all original roots.

Example body

{
  "dataset_id": "example-tree",
  "layout_version": "80a675d88f05e453",
  "node_id": "a"
}

Response · 200

Fields: GraphRootingResponse. 

{
  "dataset_id": "example-tree",
  "layout_version": "ad49ac6bc6ac4180",
  "node_count": 3,
  "edge_count": 2,
  "cluster_count": 3,
  "lod_tier_count": 1,
  "technical_roots": [
    "a"
  ],
  "layout_status": "ready",
  "warnings": [],
  "component_ids": {
    "root": "a"
  },
  "default_roots": [
    "root"
  ]
}

The response maps every previous component ID to its replacement in component_ids. Choosing the current root is a no-op that retains the version. Missing layouts return 404. Unknown nodes and versions without a saved preparation snapshot return 422; prepare older inputs again to enable rooting.

Rerooting preserves existing edges. It is distinct from PHYLOViZ’s founder-prioritised edge selection. See Technical roots.

Optional annotation reuse#

Reuse hints require an explicit layout_version. Do not reuse observations across datasets or revisions.

  • known_annotations lists retained identities with node_id, cluster_id and is_representative. A response marked annotations_cached: true omits static metadata and the tree interval and returns empty isolate/distribution lists. Restore those fields from that exact retained identity; always use new coordinates, counts and edges.
  • known_observations: [] opts into stable observation references. In later reads, send the retained IDs. A row with values_cached: true has empty values: restore only its values and use the newly returned count.
  • An isolate marked metadata_cached: true restores metadata using the retained isolate:<id> reference. If the reference was not offered, complete metadata is returned.

Reference rows may repeat equal values. Sum their counts when grouping categories. The default HTTP adapter handles these details for the viewer.

Error responses#

Request failures use a top-level detail. Catch transport failures separately from failed background jobs.

Status Meaning Typical detail
400 Invalid Newick or ancillary input, or typing conversion failed. Message string.
404 Unknown job or missing/unpublished layout. Message string.
422 Invalid schema or operation, such as an unknown root or exceeded overlay limit. Validation list, message string or { "errors": [...] }.
429 The local preparation queue is full. Message string.
500 Unexpected service failure. Unexpected server error. 
{
  "detail": "The requested prepared forest was not found; load it again."
}

A failed background job returns HTTP 200 with status: "failed", error and optional layout error_details. It is not an HTTP success for the preparation itself.
