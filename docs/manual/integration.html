PhyloLens / Library and server integration

Library and server integration

The browser viewer and the HTTP preparation service can be used independently. Choose the boundary that fits your application.

Use case Integration
Use both components Create a view with apiUrl.
Use another frontend Call the documented service HTTP API.
Use another backend or local data Supply a GraphClient adapter.

Embed the viewer

Install @phyloviz/phylo-lens. Give the container a visible width and height, then create and load the view: 

import { createPhyloLensView } from '@phyloviz/phylo-lens';

const view = createPhyloLensView({
  container,
  apiUrl: 'https://your-service.example',
});
await view.load({
  content: '(A:1,B:2)Root;',
  sourceFormat: 'newick',
});

Call view.dispose() when the host removes the viewer. The browser API README defines the public methods, events and options.

Supply your own adapter

Provide exactly one of apiUrl and graphClient. A custom adapter only needs preparation and viewport reads: 

import {
  createPhyloLensView,
  type GraphClient,
} from '@phyloviz/phylo-lens';

const graphClient: GraphClient = {
  prepareGraph: request => yourService.prepare(request),
  readViewport: (request, options) =>
    yourService.viewport(request, options?.signal),
};
const view = createPhyloLensView({ container, graphClient });

Search, region queries, ancillary updates, component listing, additional distance connections and technical rerooting are optional capabilities. Expose the controls that your adapter supports. Check view.canSetTechnicalRoot() before offering rerooting.

An adapter owns its transport and response validation. Every viewport slice must refer to the requested immutable dataset and layout version. Tree edges, component membership, subtree intervals and observation summaries must remain coherent.

The custom-client example uses the public package with an in-memory tree and no API requests. See the integration contract for required semantics and custom HTTP transports.

Use the service with another frontend

  1. Read /health and check api_version.
  2. Submit POST /api/graph/prepare.
  3. Poll GET /api/graph/prepare/{job_id} until preparation succeeds or fails.
  4. Use the returned dataset ID and explicit layout version for viewport reads.
  5. Add the search, metadata and navigation operations your frontend requires.

The service does not require the npm viewer. A running instance exposes /openapi.json and interactive /docs. The HTTP reference defines JSON shapes and errors; the server README covers installation and deployment.
