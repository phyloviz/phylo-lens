# Make initial node colors explicit and consistent

Priority: **P2**. Area: Demo defaults / visual mapping / legend.

## Evidence and scope

Initial orange, blue and purple colors are reported before a metadata field is selected; establish which mapping is active.

## Dependencies

Can start independently.

## Acceptance criteria

- [x] Use neutral initial coloring or clearly display the active mapping and legend.
- [ ] Keep category colors stable across viewport changes, filters, nodes and wheels.
- [ ] Test initial load both with and without ancillary data and after switching datasets.

## Delivery

Link implementation PRs here. Close only after regression tests, documentation/public API updates where relevant, and the acceptance criteria are verified. Reported symptoms are not confirmed root causes.

GitHub: https://github.com/phyloviz/phylo-lens/issues/15

## Implementation update — 2026-09-17

Neutral profile coloring is now the default; explicit field selection and clearing
are covered by regression tests. The demo labels the active field, resets mapping
on dataset changes, and keeps selected-profile membership visible across refreshes.
Browser validation with private researcher inputs confirmed initial neutrality,
original-ID search, a three-isolate mixed-category profile (2:1 distribution),
and return to neutral coloring. No private inputs are committed.

Color stability across changing viewport category populations remains open, as
does reconciliation of category capacity across the renderer and legends (#16).
