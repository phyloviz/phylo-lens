# Define missing-locus policy and verify typing distances

Priority: **P0**. Area: Server ingest / PhyloLib.

## Evidence and scope

Global zero-locus filtering is implemented. The reference audit confirms numerical agreement with PHYLOViZ Online; its displayed maximum of 91 is an off-by-one presentation value for actual edges whose maximum is 90.

## Dependencies

Can start independently.

## Acceptance criteria

- [x] Exclude each locus containing allele 0 in any input profile before Hamming; do not use pairwise deletion.
- [x] Report retained/excluded loci and reject inputs with no comparable loci.
- [x] Cover complete profiles, zeros, malformed tables and all-missing loci with regression fixtures.
- [x] Verify the pinned real PhyloLib runtime and compare a reference matrix with PHYLOViZ Online using recorded settings; do not require an identical MST where ties exist.

## Delivery

Link implementation PRs here. Close only after regression tests, documentation/public API updates where relevant, and the acceptance criteria are verified. Reported symptoms are not confirmed root causes.

## Verified implementation — 2026-09-17

Implemented in merged PR #20; domain separation and post-render ancillary updates
were integrated in #23 and #2. The [reference audit](../validation/typing-distance-reference.md)
checks all 81,003 PhyloLib isolate pairs and 45,753 reconstructed Online profile
pairs without a distance mismatch. Both trees have maximum 90 and total 3573;
an independent Kruskal certificate accepts their two alternative connections.

The Online export contains filtered profiles rather than a stored distance
matrix. The audit checks those profiles and reconstructs all pair distances.
The comparison script and synthetic regressions make the evidence reproducible;
raw research data remains outside the repository. Numerical acceptance is complete.
