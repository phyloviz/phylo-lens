# Example inputs and integration fixtures

This directory contains small, versioned fixtures for development, tests,
documentation, and package-consumer validation. They are not benchmark datasets.

## Newick fixtures

| File | Characteristics | Intended use |
| --- | --- | --- |
| [`newick/small-balanced.newick`](newick/small-balanced.newick) | Small unweighted tree | Parser, unit-distance fallback, and basic rendering checks |
| [`newick/with-branch-lengths.newick`](newick/with-branch-lengths.newick) | Small weighted tree | Distance clustering, preparation, and viewport checks |
| [`newick/phyloviz-spneumoniae.nwk`](newick/phyloviz-spneumoniae.nwk) | Weighted *Streptococcus pneumoniae* tree exported from PHYLOViZ, approximately 379 nodes | End-to-end demonstration with realistic labels and ancillary metadata |

The small unweighted fixture is useful for correctness tests, but it should not
be used to evaluate distance-aware LoD quality because the service assigns unit
distance when every branch length is missing.

## Ancillary metadata

[`ancillary/phyloviz-spneumoniae.tsv`](ancillary/phyloviz-spneumoniae.tsv) is a
tab-separated table that joins to the *S. pneumoniae* Newick fixture through the
`id` column.

It includes sample attributes such as country, region, year, serotype, sequence
type, and source. Nodes without a matching row remain valid and receive no value
for the unmatched fields.

Browser API example:

```ts
await view.load({
  content: newick,
  name: "phyloviz-spneumoniae",
  sourceFormat: "newick",
  ancillaryData: {
    format: "tsv",
    join_column: "id",
    content: ancillaryTsv,
  },
});
```

HTTP equivalent:

```json
{
  "format": "newick",
  "dataset_name": "phyloviz-spneumoniae",
  "content": "...",
  "ancillary_data": {
    "format": "tsv",
    "join_column": "id",
    "content": "..."
  }
}
```

## External package-consumer fixture

[`public-library-host`](public-library-host/README.md) is a minimal Vite
application that installs the tarball generated by `npm pack`.

Its purpose is to detect distribution errors that cannot be found when the demo
imports client source directly, including:

- missing package files;
- invalid package exports;
- missing runtime dependencies;
- broken TypeScript declarations;
- browser build failures in an external project.

The CI package-consumer job rebuilds this fixture from the packed artifact.

## Running the local demonstration

Start the API service:

```bash
cd code/server
python -m pip install -e '.[test,dev]'
uvicorn phylo_lens_server.main:app --reload
```

Start the browser demo in another terminal:

```bash
cd code/client
npm ci
npm run dev
```

When the browser and service use different origins, configure the service, for
example:

```bash
export PHYLO_LENS_CORS_ORIGINS=http://localhost:5173
```

## Adding fixtures

Keep repository fixtures:

- small enough for source control;
- free of personal or restricted sample data;
- accompanied by provenance and intended use;
- deterministic and stable across tests;
- separate from evaluation datasets and generated benchmark output.

Large or licensed evaluation datasets should be acquired by reproducible scripts
under the future `eval/` workflow rather than committed here.
